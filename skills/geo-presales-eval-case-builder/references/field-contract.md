# Case 字段合同

## 必填规则

| 字段 | 必填性 | 数量与规则 |
|---|---|---|
| 公司名 | 选填 | 可识别公司的公开英文主体名；默认省略 `Co., Ltd.`、`Co. Limited`、`Limited`、`Inc.`、`LLC` 等法律实体后缀，只有后缀用于区分同名实体时才保留。 |
| 业务 / 产品名称 | 选填 | 英文简洁总称。 |
| 品牌名称 | 必填 | 官方品牌英文规范写法；作为 AI 提及统计实体。 |
| 业务模式 | 必填 | 默认按当前 Case 的主要购买路径选择 `B2B` 或 `B2C`。只有企业和个人均为核心买方，且购买标准、场景和竞品基本重合时才使用 `B2B / B2C`；两类购买决策差异明显时拆分 Case。 |
| 品类 | 必填 | 客户寻找这类产品时最常用的中性市场叫法。 |
| 垂直行业 | B2B 必填 | `B2B` 或 `B2B / B2C` 必填；纯 `B2C` 留空。 |
| 目标客户 | 必填 | 1–5 个值合并在同一字段内，用 `，` 分隔；B2B 写采购 / 决策角色，B2C 写人群特征；只写角色或人群，不写关注点。值内部尽量不用逗号或顿号。 |
| 痛点 | 必填 | 2–5 个值合并在同一字段内，用 `，` 分隔，写客户找到品牌前最头疼的问题；值内部尽量不用逗号或顿号。 |
| 使用场景 | 必填 | 2–5 个值合并在同一字段内，用 `，` 分隔，写客户实际拿产品完成的任务，值内部尽量不用逗号或顿号，不能只是主题名复写。 |
| 产品特性 | 必填 | 2–5 个值合并在同一字段内，用 `，` 分隔，写选型时逐项对比的硬指标或明确能力；值内部尽量不用逗号或顿号。 |
| 差异化优势 | 必填 | 1–5 个具体赢单理由合并在同一字段内，用 `，` 分隔；值内部尽量不用逗号或顿号。作为诊断输入假设，结论以实测为准。 |
| 适用边界 | 必填 | 用一句话说明产品适用对象与主要边界；可写最主要的适用条件或不适用人群，场景或替代品类。不是目标客户，不罗列产品卖点。 |
| 主题 | 必填 | 1–3 个主题合并在同一字段内，用 `，` 分隔；只写可作为 Prompt 集合主组织单元的市场、场景或战略机会，不标注类型。Topic 名通常 2–5 个词并只表达一个核心主题；跨 Topic 的能力、特征和评价标准保留在对应业务字段，供下游派生 Attribute。主题名称内部尽量不用逗号或顿号。 |
| 官方域名 | 必填 | 官方主域名，不填第三方店铺或单个产品页。 |
| 竞品 1–3 | 最终必填 | 为确保名称与官网一一对应，恰好 3 个竞品分别编号填写；使用英文规范名称，并处于同一购买集合。输入允许 0–3 个，不足时通过竞品研究补齐。 |
| 竞品 1–3 官网域名 | 最终必填 | 分别填写在对应竞品下一行，与竞品序号一一对应；输入缺失时通过竞品研究核验补齐。 |
| 补充内容 | 选填 | 默认留空；仅承接其他字段无法表达，但会影响问题设计的重要信息。与其他字段重复或没有新增信息时省略。 |

## 补充内容的允许范围

可写：特殊购买路径，强季节性，仅在部分地区销售，Topic 局部竞品边界，官网与客户输入的关键冲突，会改变提问条件的特殊限制。

不可写：必填字段的替代文本，已有字段的重复摘要（包括换一种说法复述），泛泛品牌介绍，未经证据支持的卖点，报告结论，AI 回答或指标。

## 语言与证据

- 英文：公司的可识别主体名，业务 / 产品名称，品牌名称，竞品名称。
- 原值：URL，`B2B / B2C`。
- 中文：其他描述性字段与主题。
- 客户输入，官网事实和公开资料可以作为 Case 输入依据；无法判断，来源冲突或关键资料缺失时标记“待人工确认”。
- 不机械添加“待验证”，也不把输入假设当作已核验报告结论。

## 主题规则

- 正式 Case 可填 1–3 个主题，只写名称，不标注宽泛或细分。
- 主题可覆盖核心品类，具体人群，场景或产品机会，但彼此不能同义重复。
- Topic 回答“长期独立监测哪个市场、场景或战略机会”；Attribute 回答“希望 AI 在这些 Topic 中如何认识品牌”。只有能独立承载一组不同 Prompt 的完整机会才写为 Topic；横跨多个 Topic 的能力、特征或评价标准保留在痛点、使用场景、产品特性或差异化优势中，供 Prompt Builder 派生 Attribute。
- Tags 是下游 Prompt 的自由横向分类，不写入 Case 的“主题”字段，也不用于决定 Topic 身份。
- Topic 名应简洁，通常 2–5 个词，优先 2–4 个词，并只表达一个核心主题；该词数是命名尺度，不对中文机械按字符计数。
- 宽泛 Coverage Topic 应短于对应的细分 Depth Topic；Depth Topic 可增加一个会改变购买判断的受众，任务或场景限定，但不叠加多项约束。
- 具体受众，场景，评价标准和其他限制条件优先放入 Prompt 或下游 Attribute；主题不写完整问题，不含 Best / Top，不含监测品牌，不窄到单个客户或 SKU。

## 竞品补齐规则

- 输入已经提供 3 组竞品名称与官网，且有同一购买集合的既有核验结果时，不重复研究。
- 输入提供 1–2 个候选，只提供名称但缺官网，或尚未核验购买集合时，将已提供项作为候选交给 `overseas-geo-competitor-research` 核验和补足；未通过项自动替换。
- 输入完全未提供竞品时，以品牌，官网，“主题”字段中的第一个主题，品类，目标客户和使用场景为研究输入，从零发现并冻结 3 个正式竞品。
- 正式竞品必须进入同一次购买决策；仅功能相似，同属大行业，不同目标客户或不同采购路径的品牌不能补位。
- 只有竞品研究冻结的 `formal_competitors` 才能写入最终 Case；相邻，外围或证据不足的候选只保留在研究审计中。
