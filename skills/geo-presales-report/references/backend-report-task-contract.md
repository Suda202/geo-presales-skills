# 报告模块任务契约

## 为什么分模块

竞品表现、引用来源、品牌表达、问题机会和行动的事实来源、失败方式不同。它们不能被塞进一次“大提取”，否则一个字段错误会导致整份结果重跑，也更容易混用指标。

脚本按以下职责发任务：

| 模块 | 只允许处理的内容 | 依赖 |
|---|---|---|
| M02 | 提及率、声量占比、平均排名的解释 | `competitor` |
| M03 | 来源结构、官网引用事实、覆盖缺口 | `citation` |
| M04 | 本品表达证据的正向与风险主题 | `brand_expression` |
| M05 | 已分档问题的现状解释 | `category_actions` |
| M01 | 总览与已定稿机会结论 | `overview`、M05 |
| M06 | 后端已确定行动方向的客户化表达 | `action_context`、M02–M05 |
| M10 | 已定稿模块的最终摘要 | M01–M06 |

```json
  "protocol_version": "从任务原样复制",
  "run_id": "从任务原样复制",
  "task_id": "从任务原样复制",
  "kind": "backend_report_module",
  "module_id": "M02",
  "task_digest": "从任务原样复制",
  "status": "completed",
  "output": {
    "content": ["...", "...", "..."],
    "evidence_refs": {
      "/0": ["fact:/mention_ranking/0"],
      "/1": ["fact:/share_segments/0"],
      "/2": ["fact:/rank_performance/0"]
    }
  }

```

智能体只能声明语义任务已完成，不能声明脚本已接受。`submit-task` 校验通过后才写入正式结果。

## 证据引用

- `fact:/JSON指针`：当前模块的后端事实资源。
- `module:M05:/p0`：已接受依赖模块的输出。
- `evidence:BE-001`：一条品牌表达证据。
- `action:ACT-001`：后端行动方向。

每个非空结论都必须有引用。引用用于审计和自动检查，不写入客户可见文案。

## 失败处理

- JSON 或 Schema 错误：只修当前结果文件。
- 引用不存在：回到当前模块补正确引用，不重跑其他模块。
- 后端事实自相矛盾：停止当前模块并反馈后端，不由报告 Skill 选择一个数字继续写。
- 无法完成语义表达：保留任务待处理；不要用空数组、假数字或“数据解析异常”冒充成功。
