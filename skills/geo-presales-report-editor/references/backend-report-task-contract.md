# 报告模块任务契约

## 为什么分模块

竞品表现、引用来源、品牌表达、问题机会和行动的事实来源、失败方式不同。它们不能被塞进一次“大提取”，否则一个字段错误会导致整份结果重跑，也更容易混用指标。

脚本按以下职责发任务：

| 模块 | 只允许处理的内容 | 依赖 |
|---|---|---|
| M02 | 判断品牌未进入或进入后位置落后，并说明每个正式竞品的决胜回答胜率与正面对比优劣势 | `competitor`、`competitor_comparison_summary` |
| M03 | 判断来源主导权、官网可发现性、主题/Tag 范围内的页面机会和第三方承接 | `citation`、`page_opportunities` |
| M04 | 判断已被识别的差异点、购买顾虑和信任风险 | `brand_expression` |
| M05 | 判断已分档缺口覆盖的需求与决策阶段 | `category_actions` |
| M07 | 判断整体与主题的品牌提及、平均提及排名是否形成跨平台一致性 | `platform_consistency` |
| M08 | 判断品类认知类问题形成的市场选择标准是否覆盖问题关键属性、是否与品牌预设关键差异点契合、遗漏或冲突 | `market_perception_diagnostics` |
| M01 | 综合主诊断、跨模块关系和优先级 | `overview`、M02–M05、M07–M08 |
| M06 | 后端已确定行动路由的客户化表达，包含目标载体、我方/客户责任与复测信号 | `action_context`、M02–M05、M07–M08 |
| M10 | 已定稿模块的最终摘要 | M01–M08 |

## 证据引用

- `fact:/JSON指针`：当前模块的后端事实资源。
- `module:M05:/p0`：已接受依赖模块的输出。
- `evidence:BE-001`：一条品牌表达证据。
- `action:ACT-001`：后端行动方向。

每个非空结论都必须有引用。引用用于审计和自动检查，不写入客户可见文案。

## 任务内的综合规则

每个任务都携带 `synthesis_method` 和模块专属的 `synthesis_rules`。统一方法为：

```text
数据事实 → 状态判断 → 业务含义 → 证据边界
```

M02-M05 与 M07-M08 先各自完成单模块判断；只有六个事实模块全部被脚本接受或明确降级后，M01 才会生成并读取它们的正式结果。M01 可以建立跨模块关系，但不得把事实并存写成因果或引入新数字。M07 的实质性一致/分歧及 M08 的 included/missing/conflicting 会改变结论可信度、适用范围、差异化判断或优先级时，M01 应保留对应判断；仅在证据不足或与更重要判断完全重复时省略。完整的数据与结论映射见 [结论综合规则](conclusion-synthesis-guide.md)。

M06 不从模块分数自行判断“内容不足”。只有后端提供 `route_type` 时，才能区分信息理解、第三方信任、错误事实、负面认知与优势强化；输出需隐藏内部枚举，并把 `verification_signals` 翻译为同口径复测中的可观察变化。非 Blog 官网修改必须明确由客户执行，我方只提供修改清单或建议文案。引用 `page_opportunity_ids` 时只使用高相关页面，并把内部 Attribute/Prompt Gap 改写成具体能力、Claim 或问题缺口。

客户文案中的诊断标签统一称为“发现、竞品、验证、准确性、评价、品类认知”，在结论句中写成“发现类问题、竞品类问题、验证类问题、准确性类问题、评价类问题、品类认知类问题”。整体指标必须先拆到实际覆盖的这些意图再综合；竞品、验证、评价题面已含品牌时，其必然提及和排名不得作为独立结论。品类认知类问题只写主题下的选择标准与问题关键属性、品牌预设差异点的契合，不写品牌提及、排名或情绪。M01 应按证据覆盖整体、主题、平台共同与差异、引用和跨维度张力，不人为增加“正式结论”或“切片观察”层级。

## 失败处理

- JSON 或 Schema 错误：只修当前结果文件。
- 引用不存在：回到当前模块补正确引用，不重跑其他模块。
- 后端事实自相矛盾：停止当前模块并反馈后端，不由报告 Skill 选择一个数字继续写。
- 无法完成语义表达：保留任务待处理；不要用空数组、假数字或“数据解析异常”冒充成功。
