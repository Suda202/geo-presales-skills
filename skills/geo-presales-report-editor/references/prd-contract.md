# 售前报告诊断实现契约

## 新版适用范围

- 3 个主题、51 条 Prompt；每个主题为 10 个发现类、3 个竞品类、1 个验证类、1 个准确性类、1 个评价类、1 个品类认知类问题。
- `target_attributes` 与主题/Tag 来自评测集同一 Case；只表示希望验证的关联。
- 新版以 `diagnostic_intent + metric_scopes` 分流，旧 `question_type / funnel_intent` 仅作 v1 回放兼容。

## 指标与诊断

- 品牌进入率、指定竞品内声量、平均提及位置、问题机会：只使用有效发现类问题回答。
- 主要引用生态：只使用有效 Discovery 回答的引用；其他意图的引用另列范围。
- 竞品：逐题输出目标品牌胜、竞品胜、平局或不明确，以及判断强度；后端按每个正式竞品汇总唯一的决胜回答胜率、胜负/平局/无法判断计数及正面对比优劣势；不进入情绪。无决胜回答时胜率为 `null`，不设总体胜率。
- Attribute：Validation 与同主题/Tag、同 Attribute 的 Discovery 配对，输出 Strength、Opportunity、Objection 或 Unknown。Attribute 由主题或 Tag 承载，不作为客户报告或跨平台分析的一等字段。
- Accuracy：对照官方真值与回答主张，并保存错误来源。
- Sentiment：只使用 Sentiment 问题中的目标品牌评价；中性不进入正向率分母。
- Market Perception：后端将主题下的选择标准与问题预设关键属性、品牌预设差异点对齐为 `included / missing / conflicting / insufficient`，形成独立 M08；只回答选择标准是否覆盖关键属性、是否与品牌差异点契合，不进入品牌 Visibility，也不作为输赢或归因数据。
- Model Consensus：后端基于同口径匹配 Discovery Prompt 生成整体与主题级跨平台状态。主题的提及或排名为 `mixed` 时，可判断该主题的跨平台表现尚未稳定；Attribute 只用于分析解释，不作为显性字段或独立跨平台状态。
- Action Routing：后端基于配对 Attribute、准确性、品牌表达和引用证据，把行动正式路由为信息理解缺口、第三方信任缺口、错误事实纠正、负面认知重构或已有优势放大，并同时给出目标载体、责任分工和可见度/引用/品牌表达/准确性复测信号。单个低指标不能直接生成内容动作。
- Page Opportunities：后端先按主题或主题+Tag 扫描官网相关页面，再把 Attribute/Prompt Gap 作为具体修改目标，独立判断页面相关性和 Citation 状态，形成四象限，并结合 AI Gap 严重度和页面价值给出 priority；不能只扫描已引用页面。

提及率排名是同一 Discovery 样本内按提及率比较得到的相对名次。平均提及位置是对象在被提及回答正文中的首次合格出现位置取平均，不是提及率排名，也不是模型对品牌优劣的语义排序。无提及时展示 `—`。

情绪适用性独立于 Discovery：后端已确认适用于 Sentiment 的记录必须进入情绪聚合，即使它不属于 Discovery 或同时带有其他诊断意图；这类记录仍不得进入正式 Visibility。

## v1 兼容

历史单主题、Generic/Branded 输入可继续回放，但新报告不得沿用其分母解释。缺少独立 Attribute、竞品结果、准确性和品类认知数据时，模块留空或降级，不由编辑器补算。

## 发布门禁

阻断：批次或 schema 不一致、诊断范围不明、有效回答为零、主题/Attribute 引用失配、引用主样本不是 Discovery、情绪或竞品结果混算、指标不变量失败、任务未完成或缺追溯哈希。

允许显式降级：某一诊断意图无有效样本、未知来源无法分类、后端未提供竞品汇总、购买框架正式诊断、跨平台一致性或行动上下文。降级不得写成业务零值，也不得由报告编辑器从原始回答补算。

行动仍写入现有 M06 和上传 CSV 字段，不扩展后台 schema。诊断范围覆盖整个官网与外部信源；我方直接内容交付只含官网 Blog 和约定第三方信源，非 Blog 官网页面由客户修改上线，企业内部事实与审批由客户相关团队提供或确认。
