# GEO 售前结论综合规则

## 目标

结论不是把页面数字换一种说法，而是让客户知道：当前属于什么问题、证据指向哪里、哪些解释仍不能成立、下一步先解决什么。每条结论至少承担一种作用：诊断、边界、关系、优先级或行动。只复述数值且不改变判断的句子应删除或合并。

## 通用结论单元

先把每条候选结论写成四个部分，再压缩成客户文案：

```text
数据事实 → 状态判断 → 业务含义 → 证据边界
```

- **数据事实**：只取后端正式结果，并保留其统计范围、分母和支持样本。
- **状态判断**：回答“缺席、进入后位置落后、证据覆盖不足、差异点已形成、信任风险存在”等明确问题。
- **业务含义**：说明这会影响品牌进入回答、购买比较还是信任判断。
- **证据边界**：说明当前不能进一步证明什么，避免把相关性写成因果。

四部分用于内部判断，不要求客户文案机械写满四句。最终只保留客户需要的事实、判断和必要边界；如果一句话只有数据事实，没有新增状态、含义或边界，它不是完整结论。模块允许保留必要数字，但每组数字至少要汇总成一个状态判断。

## 先固定统计范围

### 统一诊断意图名称与职责

客户文案只使用以下六个名称；英文枚举和旧称只可留在内部字段或契约中：

| 内部字段 | 客户名称 | 主要分析职责 |
|---|---|---|
| `discovery` | 发现 | 用户未指定目标品牌时，品牌能否进入回答，以及进入后的平均提及位置 |
| `competitor` | 竞品 | 与具体正式竞品直接比较时的胜负、情绪、竞争层级和证据主题 |
| `verification` | 验证 | 哪些产品事实、能力和官网来源被识别与采用 |
| `accuracy` | 准确性 | 回答事实是否与官方真值一致；无正式样本时只写未覆盖 |
| `evaluation` | 评价 | 被问到目标品牌后形成的正向、负向或保留认知 |
| `category_awareness` | 品类认知 | 无品牌品类问题体现的选择标准和权衡 |

不得在同一报告中混用“发现型、纯发现型、竞品比较、功能核实、准确性诊断、品牌评价”等名称。尤其不要另造“纯发现”口径；需要说明范围时直接写“发现类问题”或“发现类问题结果”。

按指标分别选样本，不把诊断意图当作互斥总开关：正式可见度和主要引用生态只纳入 Discovery；情绪直接纳入完整 `analysis_type=sentiment` 数据。记录不是 Discovery，只代表它不能进入正式可见度，不能据此删除它的有效情绪结果；记录带有 `visibility` 处理标记，也不能据此把非 Discovery 样本并入正式可见度。完整定义见 [统计范围与客户指标命名契约](metric-scope-and-copy-contract.md)。

不同数据回答不同问题，不能混成同一批样本：

| 数据范围 | 回答的问题 | 可以写 | 不能写 |
|---|---|---|---|
| 发现 | 发现类问题的回答是否提到品牌、平均提及位置如何 | 提及、指定竞品内声量、平均提及位置 | 用其他诊断中必然出现的品牌名证明品牌进入 |
| 竞品 | Competitor 回答如何比较一对品牌 | 每个正式竞品的决胜回答胜率、胜负/平局/无法判断计数、明确正面对比优劣势 | 另写总体胜率；改写成品牌正负情绪或市场份额 |
| 验证 | Validation 与配对 Discovery 如何反映目标 Attribute | Strength、Opportunity、Objection，以及被采用的官网事实 | 把 `target_attributes` 直接当成已形成认知 |
| 评价 | 完整 `analysis_type=sentiment` 数据如何评价目标品牌 | 正向特点、保留意见、风险和信任障碍 | 再按某个 `diagnostic_intent` 筛选；写成品牌已被主动提及、已进入真实询价或已被采购方选用 |
| 准确性 | Accuracy 的官方真值与回答主张是否一致 | 准确、不准确、无法判断和错误来源 | 由编辑器自行检索或重判真值；无样本时补写结论 |
| 品类认知 | Market Perception 如何定义主题下的选择框架 | 关键标准和权衡 | 写成目标品牌 Visibility |
| 主要引用生态 | Discovery 回答使用哪些来源、官网哪些页面被采用 | 来源结构、页面覆盖、证据层级 | 混入其他意图引用或用引用直接证明品牌会获得推荐 |
| 跨平台一致性 | 匹配 Discovery Prompt 在可比平台上的整体与主题提及、平均提及位置是否稳定 | 各平台整体或具体主题结果一致、分歧或证据不足 | 把 Attribute 单列为跨平台状态；写成全网共识、长期趋势、平台机制原因或单平台优化结论 |

客户文案通常不需要解释内部题型。只有为避免指标误读时，才使用上述六个固定名称；标签单独展示时用“发现、竞品、验证、准确性、评价、品类认知”，结论句中写成“发现类问题、竞品类问题、验证类问题、准确性类问题、评价类问题、品类认知类问题”。不要暴露 `diagnostic_intent`、`metric_scopes`、通用题或品牌题。竞品、验证和评价的问题本身可能出现目标品牌，因此题面驱动的提及和平均提及位置不能证明发现表现；该规则只用于编辑侧过滤，不写成客户文案。

### 整体指标不等于发现表现

整体提及率可能汇总六类诊断意图，而发现才回答“用户未指定品牌时是否自然进入回答”。因此必须先读取整体指标，再按六类意图拆开；不得把整体提及率直接称为发现率、自然可见度或推荐表现。

当整体与发现方向不同，总览必须说明差异。例如整体有提及、发现为零，正确判断是“现有露出来自其他已覆盖诊断意图，品牌尚未在发现类问题中进入回答”，而不是把整体提及写成品牌已有发现基础。只需用范围和结果说明一次；不解释提问方式、题型机制或“为什么必然提及”，后续模块直接分析有证据的意图。

竞品、验证或评价题若题面已包含品牌，则“品牌 100% 提及、平均提及位置第 1”不进入客户文案。不要输出提问方式、题型机制或指标过滤解释；只保留后端提供的具体比较、事实识别或评价结果。

情绪是与诊断意图正交的分析类型。后端已给出情绪聚合时，直接使用完数；只有明细时，仅按 `analysis_type=sentiment` 取数。Competitor、Evaluation 或其他诊断意图只要 `analysis_type` 为 `sentiment` 都进入情绪，不得只保留 Evaluation，也不得因为不属于 Discovery 而删除。

## 客户语言二次改写

完成事实判断后，再做一次只面向客户的改写。使用以下固定形状：

```text
统计结果呈现什么 → 客户现在可以得出什么判断 → 哪个解释仍不能成立
```

行动模块另用：

```text
要解决的具体问题 → 准备什么以及如何提供 → 方便谁完成什么判断
```

| 不要写 | 改写方向 |
|---|---|
| 尚未进入供应商候选名单、自然候选、自然进入缺口 | 在可见度统计中未被提到；因此目前谈不上平均提及位置靠前或靠后 |
| 情绪分析评价正面，所以品牌已经进入推荐 | 情绪分析的问题本身会提到品牌；正面只说明品牌印象，不证明可见度 |
| 证据层级、证据承接、实绩验证、系统级验证 | 直接写缺少哪类可核验信息；制造业可落到适用工厂、型号证书、质量、量产和案例，其他行业按实际采购条件改写 |
| RFQ | 询价 |
| 某类高门槛项目需要单独核实 | 只有该场景是实际目标且证据明确时，写清要核实什么材料；否则删除 |
| 公开资料不能替代真实表现验证 | 写清现有资料能说明什么、采购判断还缺什么；没有具体缺口时删除 |

默认使用“回答、引用、官网页面、选型方”等业务词，不反复写 AI，也不把所有诊断压成采购叙事。发现讲用户未指定品牌时能否进入回答，竞品讲相对表现，验证讲事实识别，评价讲品牌认知，品类认知讲选择标准，准确性讲事实正误。只有问题明确对应采购方、制造商初选或采购选型时才使用“采购”。每句必须改变客户判断、优先级或行动；删除后不影响这些内容的句子直接删除，不为固定条数补齐。

### 删除指标元说明

客户报告不是指标词典。除非用户明确要求解释统计口径，不要写“该指标表示正文首次出现顺序”“平均提及位置不能视为推荐强弱”“引用份额不等于可见度”“据此不能判断”等句子。这些属于内部校验规则；客户侧直接给出发现、竞争位置、证据缺口或行动结论。凡句子只在解释指标含义、限制误读、筛选机制或题型，都删除，不用同义改写填充篇幅。

## 从哪些数据得出哪些结论

| 数据组 | 必须一起读取的数据 | 主要结论职责 | 不足时如何处理 |
|---|---|---|---|
| 样本与覆盖 | 有效回答数、问题范围、有效分母、缺失或降级状态 | 判断结论适用范围和证据稳定性 | 不把无效回答、序号断档或任务总数当作业务零值 |
| 品牌与竞品可见度 | 提及率、指定竞品内声量、平均提及位置、正式竞品集合 | 判断品牌是未进入、进入后位置落后，还是已形成相对优势 | 没有提及时只写缺席；没有主题证据时不解释竞品为何领先 |
| 竞品正面对比 | 决胜回答胜率、双方胜场、平局/无法判断、优势/劣势主题与证据 | 判断模型明确选边时的相对胜势及具体比较差距 | 无决胜回答时胜率写 `null`；不另算总体胜率，不混入一般情绪或品牌常识 |
| 问题机会 | 已分档问题、问题文本、需求主题或决策阶段 | 判断缺口覆盖哪些需求、是单点还是跨阶段 | 只有分档没有主题时，只写机会广度和状态，不补行业意图 |
| 引用来源 | 来源类型、热门域名/页面、官网引用量、官网页面列表 | 判断来源主导权、官网可发现性、证据层级和第三方承接 | 没有页面类型或内容证据时，不评价页面质量 |
| 官网页面机会 | 主题/Tag 官网候选范围、内部 Attribute/Prompt Gap、页面相关性、Citation 状态、AI Gap 严重度、页面价值和后端 priority | 判断哪些页面值得为当前主题/Tag 强化、哪些属于 Citation Gap，以及具体应补强的能力、Claim 或问题缺口 | 缺失 `page_opportunities` 时不从已引用页面反推全站机会；不把 Attribute 做成客户可见字段，也不由报告侧重算优先级 |
| 品牌表达 | 正向/中性/负向证据、主题、支持样本和明确比较语句 | 判断已被识别的差异点、购买顾虑和信任障碍 | 没有支持度时降低强度；不把被问及后的评价当成自然可见度 |
| 品类购买框架 | 后端 Market Perception 对齐状态、预设差异点、市场标准、支持样本和证据 | 判断市场是否把品牌关键差异点当作购买标准 | 缺失时降级；不由编辑侧重读原始回答自判，不写成 Visibility 或归因 |
| 跨平台一致性 | 后端已确认的样本对齐信息，以及整体与主题的提及一致性、平均提及位置一致性和共识强度 | 判断品牌在可比平台上的结果是否形成相对稳定共识 | 缺失时降级；不由编辑侧拼接平台样本、计算阈值或解释平台机制 |
| 行动上下文 | 后端方向、状态、关键证据、动作模板 | 把已确定的问题转成不同的行动和验证目标 | 缺失时行动模块留空或降级，不由报告侧重新判定 |

这些数据不是平均分配给所有模块。竞品数据负责“有没有进入、进入后在哪里”，引用数据负责“模型采用了什么证据”，品牌表达负责“被问到后如何评价”，问题机会负责“缺口落在哪些需求”。总览才负责把这些已定稿判断放在一起，选出最影响客户决策的三至五条。

## 多维分析顺序

1. **样本与口径**：只使用有效回答和已确认分母，确认整体指标包含哪些诊断意图。
2. **诊断意图**：分别分析发现、竞品、验证、准确性、评价、品类认知；缺失的意图明确未覆盖，不从其他意图补判。
3. **整体与主题**：整体先定主状态，主题再定位差距落在哪里；不同主题由不同竞品占位时，分别写竞争结构。
4. **平台共同与差异**：先写各平台共同支持的结论，再写平台间不同的提及、位置、竞品占位或证据结构。不要用笼统的“一致/不一致”代替具体差异。
5. **引用结构**：判断发现类问题采用哪些来源、官网事实在哪些意图被采用，以及是否存在“可被读取但未进入发现”的张力。
6. **跨维度关系**：寻找会改变判断的张力，如发现为零但评价正向、验证采用官网事实但发现官网引用为零、评价正向但竞品比较偏负向。
7. **优先级**：只保留会改变问题性质、客户优先级或行动方向的结论；数字更大不自动等于更重要。

这些都是不同数据维度的分析结论，不区分“正式结论”和“切片观察”。可以写“整体结论、主题结论、平台共同结论、平台差异结论、诊断意图结论”，但只写后端实际覆盖且能改变判断的维度，不为凑齐维度补句子，也不反复使用范围限定词。证据边界仍需保留：不外推全网，不猜平台机制，不把相关性写成因果。

选择总览结论时，按以下顺序取舍：会阻断品牌进入或购买判断的状态、跨多个问题重复出现的缺口、两个以上模块相互支持的关系、后端已有行动能够承接的诊断。不同条目必须承担不同作用，不能都在证明同一个低指标。

## 数据到结论映射

### 数据总览

使用 `overview` 和已定稿的 M02-M05、M07-M08。先确定一个主诊断，再选三至五条互不重复的判断。

| 事实组合 | 主诊断 | 正确表达 |
|---|---|---|
| 提及率为 0、平均提及位置为 `-` | 缺席问题 | 当前不是位置靠后，而是尚未获得有效提及 |
| 已有提及、提及率排名明显靠后 | 竞争进入问题 | 已进入部分回答，但提及率排名靠后，相比竞品处于后位 |
| 已有提及、平均提及位置明显靠后 | 回答内位置问题 | 已进入部分回答，但被提及时在正文中的平均首次出现位置靠后 |
| 官网已有引用、可见度仍弱 | 官网采用范围问题 | 官网内容能被找到，但品牌在可见度统计中仍未被提到 |
| 正向差异点明确、风险集中在证书/评价/售后 | 产品特点与采购资料不匹配 | 回答能识别产品特点，但采购方仍缺少证书、评价或售后信息来完成判断 |
| 多项指标稳定且风险低 | 维护问题 | 维持已有优势，并观察波动与新增风险 |

总览建议覆盖五种角色中的三至五种：可见度状态、竞争边界、机会广度、跨模块张力、优先顺序。不要让标题和所有要点都重复“提及率低”。

后端提供同口径全品牌提及率排名时，核心结论和可见度总结都应至少一次写明“提及率排名第 x/N”及相对竞品的位置判断。不得用“平均提及位置 #8”代替“提及率排名第 49/125”：前者只表示被提及时在正文中首次出现的平均位置，后者才表示同口径品牌间的竞争位置。

Task 190 反例：把非 Discovery 回答混入会得到 7.1% 的虚高提及率；只用 Discovery 后为 1.6%，提及率排名第 49/125。这个例子仅用于识别统计口径故障，不得将 Singderm 数字套用到其他报告。

### 竞品表现

使用正式竞品的提及率、指定竞品内声量占比和平均提及位置。

1. 先判断是“未进入”还是“进入后位置落后”。零提及时不存在排名差距。
2. 声量占比只代表冻结的目标品牌和正式竞品集合，不得写成全市场占有率或市场主导地位。
3. 只有事实资源提供逐主题提及或已接受的主题证据时，才能说明竞品优势集中在哪些需求；没有主题证据时只写指标边界。
4. 页面字段统一称“平均提及位置”；它表示品牌在被提及回答正文中的首次合格出现位置取平均，不是模型对品牌优劣的语义排序，也不是按提及率高低比较得到的“提及率排名”。
5. 目标品牌和客户提供的竞品全部为零时，只能写当前数据无法比较相对表现；不得说客户竞品选错、建议重新选择或替换正式竞品。
6. 全部为零时，现有结果通常无法区分“问题没有覆盖共同采购场景”和“这些品牌在该范围内出现较少”。证据不能区分时并列保留两种可能，不自行选择原因。
7. 回答中出现的其他品牌只代表当前回答实际提到的对象。需要增加对照时，只能作为补充观察对象，并先核对业务是否相近；不得自动替换客户提供的竞品。
8. 对每个正式竞品只把 `target_wins / (target_wins + competitor_wins)` 称为“竞品胜率”。分母只含明确选出目标品牌或竞品的决胜回答；平局与无法判断保留为计数边界，不进入分母。
9. 没有决胜回答时胜率为 `null`，客户文案写“当前没有决胜回答，无法计算胜率”，不得写 0%。不得另写“总体胜率”或“全回答胜率”。
10. 胜率必须与 `decisive_answers / target_wins / competitor_wins` 一起读取。决胜回答少时，应说明样本边界；不得只报高百分比制造确定性。
11. 优势与劣势只来自后端已确认的明确正面对比主题，并保留比较维度、支持样本和证据引用。一般正负情绪、Discovery 提及率和品牌常识不能充当优劣势证据。
12. 若竞品题面已经写出目标品牌与对手，则目标品牌 100% 提及、平均提及位置第 1 直接从客户文案中删除；不得输出“题面已写出品牌”“属于题型机制”“不能据此判断”等元解释。竞品结论只转向后端提供的决胜结果、竞争层级、比较维度和证据主题；没有这些证据时省略该条，不用题面必然提及填充竞品模块。

有用结论要区分两个问题：Discovery 回答中的差距属于进入、位置还是范围问题；Competitor 回答明确选边时，品牌对每个正式竞品的胜率和具体优劣势是什么。两组样本不能混成一个结论。

### 引用来源与官网覆盖

结合来源类型、热门域名/页面、官网引用量和官网页面列表，依次判断：

1. **来源主导权**：回答主要依赖官网、媒体评测、企业网站、UGC 还是其他来源。
2. **官网可发现性**：是否已有官网页面被实际引用。已有引用时不得写“官网不可抓取”。
3. **证据层级**：引用集中在首页/联系页，还是产品、证书、政策、案例等决策页面。
4. **站外承接**：高频外部来源属于榜单、评测、购买指南还是机构资料，目标品牌是否缺少同类第三方承接。

当引用主要落在首页或联系页时，可以写“当前更多证明品牌存在，而非提供购买决策证据”；不能写“官网引用没有转化为推荐”这类确定因果。只有页面清单和引用量明确支持时，才能判断集中度；不得自行计算新的正式占比。

在后端引用聚合明确支持时，还可做三类结构判断：

- **份额集中度**：引用份额高度分散时，可写“该品类尚未形成主导信源，回答证据基础仍然开放”；少数域名集中占据时，写清由哪些头部信源占位。两种情况都只描述当前引用结构，不承诺进入难易。
- **官网被采用的角色**：官网引用只落在产品页时，可写“官网当前被当作产品事实来源，尚未在品类比较、选型或购买指南语境中承担证据”；这与首页/联系页的存在性判断是不同层级，应分开表达。
- **竞品引用缺口**：同一批引用中出现“引用了正式竞品但未引用目标品牌”的来源时，这些来源是站外承接的优先候选，可点名具体域名或页面；只有引用清单直接支持时才能这样写，不得从竞品可见度反推。

来源名称的细分程度必须服从后端分类。“其他来源”没有进一步分类时就保留该名称，不猜测具体来源；“企业网站”只有在数据能确认其属于非监测对象的其他企业官网时才这样写。

#### 官网页面机会：相关性与 Citation 分开

页面机会只使用后端 `page_opportunities`。正确顺序是：主题或主题+Tag 划定官网扫描范围 → 用内部 Attribute / Prompt Gap 判断页面是否值得为该范围修改、具体改什么 → 再叠加 Citation 状态 → 结合 AI Gap 严重度和页面价值读取后端 priority。不得从 `brand_official_pages` 的已引用页面清单反推全站机会。

| 页面状态 | 正确判断 | 行动边界 |
|---|---|---|
| 高相关 + 已引用 | 页面已进入引用来源，并与当前主题/Tag 下的具体能力或问题缺口高度相关 | 优先强化对应能力、Claim 或回答结构；“已引用”不等于页面所有表达都已充分 |
| 高相关 + 未引用 | 页面方向与当前能力/问题缺口一致，但尚未进入引用来源 | 作为 Citation Gap，检查表达清晰度、可提取性和可核验事实；不能仅凭未引用断言页面低质量或权威性不足 |
| 低相关 + 已引用 | 页面会被回答使用，但与当前主题/Tag 的具体缺口关系弱 | 一般不为当前范围硬改；可保留其原有作用 |
| 低相关 + 未引用 | 对当前主题/Tag 基本没有优化价值 | 忽略，不为凑行动数量纳入 |

四象限只决定机会类型，不替代后端优先级。高相关已引用通常具有较高杠杆，但最终顺序仍服从相关性、AI Gap 严重度、Citation 状态、页面价值和后端 `priority/priority_score`；报告侧不得自行加权。

Attribute 不是客户报告的一等字段。内部可以用 `attribute_ids` 或 `prompt_gap_ids` 证明建议具体针对什么，对外按主题/Tag 组织并写成“强化本地存储、无需订阅等能力表达”或“补充持续录像问题所需事实”，不得展示 Attribute/Prompt Gap 英文枚举。

### 品牌表达与风险

使用品牌表达证据、情绪结果和已提供的支持度。

1. 将“被认可的品牌特点”和“阻碍购买的风险”分开，不把最终选择竞品自动判成目标品牌负面。
2. 主题强度必须匹配支持样本。只有一条正向样本时，可拆解其表达侧面，但不能称为多条高频共识。
3. 优先寻找正负之间的张力，例如“设计获得认可，但证书、来源和售后证据不足”。这比罗列关键词更有决策价值。
4. 竞品差异只能引用明确比较证据：对方具体赢在专业历史、产品信息、第三方评价、退换保修还是服务基础；不得用品牌常识补写。
5. 不在客户结论中反复解释中性是否进入正负比例，除非页面口径本身存在歧义且用户要求说明。
6. 情绪分析的问题本身会提到目标品牌。即使全部评价正面，也只能说明公开信息形成的品牌印象，不能写成已进入真实询价、供应商筛选或采购结果。风险证据若来自具体型号、能力或连接条件，按型号和使用场景说明取舍；不得把型号差异改写成品牌负向情绪比例，负向情绪为零时也不在客户文案中专门强调零值。
7. 风险必须落到具体缺口。只有“需核实”“门槛较高”“公开资料不能替代验证”等提醒，但没有适用场景、具体对象和所需材料时，删除而不是润色。
8. 证据支持时区分负面认知的广度：同一负面主题跨多个问题重复出现，与只在个别题目中被触发，是不同严重度的问题，应写清覆盖范围；不得把单题负面写成普遍认知，也不得把跨题重复淡化成个别现象。
9. 正向表达不只用来平衡负面：应检查被认可的特点是否与品牌预设差异点一致。正向集中在非预设维度时，可写“市场认可的特点与品牌主打差异点不同”，供客户判断定位表达；有正式 M08 时该判断交由品类认知模块承载，不重复展开。

### 品牌进入机会

只解释后端已分好的 `p0/p1/p2`：

- `p0`：说明缺席覆盖哪些需求主题，以及缺口是单点还是跨多个决策阶段；不得写“排名第 0 位”。
- `p1`：说明已经进入哪些回答但平均提及位置仍需优化。
- `p2`：说明哪些主题已进入较靠前位置，值得保持观察。

空档必须留空。该模块只描述现状，不写建页、投放、发稿等行动。

### 品类认知/购买框架

只使用后端正式 `market_perception_diagnostics`，按主题比较品类认知类问题形成的 `market_criteria`、问题 `target_attributes` 与评测前预设的品牌关键差异点。这里分析的是“市场实际用什么标准选择”与“问题预设、品牌希望被识别的关键属性是否契合”，不是品牌在回答中的提及表现。

| 后端状态 | 可以写 | 不可以写 |
|---|---|---|
| `included` | 该主题的市场选择标准已包含问题预设属性，且与品牌预设差异点契合，品牌在该标准上有明确评价位置 | 品牌因此一定获胜或获得推荐 |
| `missing` | 该主题的市场选择标准未覆盖问题预设属性，品牌差异点暂时没有对应的评价位置 | 市场不需要该能力；缺失直接导致低 Visibility |
| `conflicting` | 该主题的市场选择标准与问题预设属性或品牌预设差异点存在明确冲突，需要写清冲突双方和适用范围 | 品牌定位错误或必须立刻更改定位 |
| `insufficient` | 当前样本或属性映射不足以判断市场选择标准与问题预设属性、品牌差异点是否契合 | 用原始回答、品牌常识、品牌提及或其他题型补判 |

每条实质性结论同时读取主题、标准化 Attribute、问题 `target_attributes`、品牌预设差异点、`market_criteria`、支持样本和证据引用。先做属性对齐，再按 `included / missing / conflicting / insufficient` 输出结论；不得用品类认知类问题的品牌提及、排名或情绪代替对齐结果。这里判断的是选择标准是否为品牌差异化提供评价位置，不是品牌可见度、直接竞品输赢原因，也不是流量、线索或成交归因。只有后端 `action_context` 提供方向时，M06 才能承接行动。

### 跨平台一致性

优先使用后端已经对齐市场、语言、采集窗口和 Prompt 的 `platform_consistency`：

1. **先看可比性**：至少两个平台具有匹配的 Discovery 样本；后端标记证据不足时，只写当前无法判断跨平台稳定性。
2. **先提及、后位置**：先判断品牌是否在各平台获得提及；只有获得提及时才解释平均提及位置。所有平台均未提及时，不存在位置差异判断。
3. **分别表达两个维度**：提及一致但位置分歧，表示品牌已经跨平台进入相关回答，但竞争位置尚不稳定；不得合并成笼统的“表现不一致”。
4. **限定一致性含义**：一致表示可比平台传递的品牌信号较为稳定，可作为较强的共识信号，但不等于全网共识、长期趋势或市场事实；分歧表示共识尚未形成，也不等于某个平台“更差”。不得把这一表达升级为效果承诺或平台机制解释。
5. **不从差异猜原因**：没有引用、页面或其他模块的直接证据时，不把平台分歧归因为特定来源、页面结构、模型机制或内容缺失。
6. **不直接生成平台特供行动**：M07 只诊断稳定性。M06 仍服从后端 `action_context`，不得因为平台分歧自行提出“专门优化 ChatGPT/Gemini/Perplexity”。
7. **正式层级只到整体与主题**：`scope_type` 只允许 `overall / topic`。整体用于判断主诊断是否稳定，主题用于定位具体哪些主题形成一致或仍有分歧。
8. **只使用后端状态**：`mention_consistency`、`position_consistency` 与 `consensus_strength` 均由后端正式提供。报告侧不得根据各平台数值自行定阈值。
9. **主题分歧代表判断未稳定**：某个主题的提及或排名状态为 `mixed` 时，可写“该主题的跨平台判断尚未稳定”。Attribute 可用于解释该主题的具体差异点，但不单独输出跨平台状态。
10. **不猜来源权重**：平台分歧可以说明证据基础仍混杂，但不能直接断言各平台给不同来源分配了不同权重。只有引用数据直接支持时，M01 才能写有限关系。

若 `platform_consistency` 缺失，但报告页面、导出文件或只读接口已经提供同市场、同语言、同采集窗口、同 Prompt 的后端筛选聚合结果，可以直接比较这些已确认数值，写“平台共同结论”和“平台差异结论”。此兼容模式不得自行生成 `mention_consistency`、`position_consistency`、`consensus_strength` 等状态，不得手算阈值，也不得猜差异原因。若样本是否对齐无法确认，只能分别陈述各平台结果，不能宣称跨平台稳定或一致。

客户表达建议使用：

| 后端结果 | 正确表达 |
|---|---|
| 多个平台提及与排名均一致 | 可比平台对品牌的进入状态和平均提及位置较为一致，形成相对稳定的共识信号 |
| 有的平台提及、有的平台缺席 | 平台间的品牌进入结果存在差异，尚未形成稳定的共识 |
| 各平台均有提及、排名不一致 | 品牌已进入各平台相关回答，但平均提及位置仍存在平台差异，共识尚未完全形成 |
| 各平台均未提及 | 可比平台均未提及品牌；缺席不是单一平台现象，但不能外推为全网缺席 |
| 可比平台或匹配样本不足 | 当前数据不足以判断跨平台一致性 |
| 某主题的提及与排名均一致 | 可比平台对该主题的品牌进入和平均提及位置判断相对稳定 |
| 某主题的提及或排名为 `mixed` | 该主题的跨平台判断尚未稳定，应保留具体的平台差异边界 |

### 下一步行动

Chapter 5 的方法论要求先定性，再定路由：先判断是理解缺口、信任缺口、错误事实、负面认知重构，还是优势放大；再决定是站内页面、站外信源，还是两者并用。站内页面负责形成或强化可抽取的信号，站外信源负责独立佐证、更新现有提法或改写叙事。不要把低 Visibility 直接等同于内容不足，也不要把一个页面当作单点解决方案。

| 后端路由 | 成立条件与行动重点 | 客户文案边界 |
|---|---|---|
| `comprehension_gap` | 低进入、低验证：品牌能力尚未被正确识别。优先做站内表达，把事实放到适合承载它的页面里，写清是什么、适用于谁、AI 能如何抽取。 | 不把单个低指标自动解释成内容缺失；不承诺只靠新页面必然进入回答。 |
| `trust_gap` | 低进入、验证已足：品牌能力已被识别，但外部独立佐证不足。优先做站外承接，先更新已有提及，再进入已有信源，最后才新建信源；官网只补解释。 | 不把继续增加官网自述当作主要解法；没有证据时不猜具体平台或媒体。 |
| `accuracy_correction` | 已有错误主张或错误来源。官网错则改官网，外部错则纠正对应来源，并补足更准确的公开事实。 | 不用新内容掩盖持续被采用的错误来源；无官方真值时不自行判错。 |
| `objection_reframe` | 已确认具体负面认知。用真实事实说明适用范围、取舍和边界，必要时站内重写与站外影响一起做，目标是重构叙事，不是辩解。 | 不机械否认真实短板，不编造客户结果，不把“品牌说没有问题”当成纠正。 |
| `strength_amplification` | 已形成可复述的优势。把同一优势在多个相关 surface 上放大，让站内、第三方和比较型内容一起承接。 | 不把单条正向样本放大成市场共识，也不把一个页面当作足够。 |

站外承接有固定优先级：先更新已有提及，再进入已有信源，最后才创建新信源。只有当现有提法无法承接时，才走新增来源，而不是默认从零开始。

#### 站内行动：多语境与三问顺序

回答引擎不按“一个关键词一个页面”取证，同一能力需要在站内多个相关语境出现才能形成稳定信号。因此站内行动不写成“新建一个页面”，而按三问展开，且只使用后端 `page_opportunities` 已确认的页面证据：

1. **这个能力有没有承载页面？** 没有则建；有则按“可被抽取”检查——AI 能否从页面直接取出一条具体主张。表述含糊、只有营销形容词的页面，即使主题对口也抽取不出事实。
2. **还有哪些页面可以自然补入提及？** 优先顺序：已被引用的页面 → 官网引用量较高的页面 → 首页、价格页、对比页等高权重页面。该顺序只在后端页面证据覆盖时写入具体页面，否则只写选择原则。
3. **怎么补入？** FAQ 结构机械但易抽取，可用于补充；把能力表述编织进正文更持久。两者都要通过编辑测试：一个不知道优化计划的编辑读到这句话不会觉得突兀。堆砌式 FAQ 墙和硬塞提及不写入建议。

#### 异议行动的三条细则

`objection_reframe` 成立时，除“重构而非辩解”外还应表达：

- **沉默即失守**：品牌对该负面话题没有任何内容时，回答只能采用外部负面表述；此时“先有承载内容”本身就是行动的一部分。
- **真实短板承认并框定**：证据显示短板属实时，行动写成“说明适用范围和取舍”，不写否认。对真实短板的否认会与外部证据冲突，反而降低可信度。
- **重构要跨多个 surface**：只改一个页面不足以改变叙事，重构表达应同时出现在站内相关页面和可影响的第三方信源；具体信源仍受后端 `target_surfaces` 约束。

#### 站外行动的表述细则

- 站外承接的价值在“来源怎么描述品牌”，不在链接本身；更新已有提及时，行动写清要把哪句过时或缺失的表述改成什么方向，不写成“获取外链”。
- 更新已有提及时优先写有现成关系的对象（集成伙伴、合作方、已合作媒体），其次才是无关系的第三方；只有后端证据能区分时才排序。
- 榜单和对比文章可以承接，但不写成唯一或主要动作；行动组合中应保留评测、目录、社区等其他类型，避免把承接押在单一体裁上。
- B2B 与消费类信源结构不同：B2B 偏行业目录、评测平台和伙伴页面，消费类偏社区、点评和内容平台。只有品类明确时才按对应轨道点名信源类型，不跨轨道套用。

客户文案按“可被抽取”而不是纯 SEO 写：用直接、具体、自然的句子；FAQ 可以补充，但嵌入正文的表达更强。遇到 objection 时优先重构而非防御，避免把真实短板写成虚假否认。

#### 最后定义复测信号

`verification_signals` 只允许四类，`expected_impact` 应写成同市场、语言、Prompt 与可比采集口径下能观察到的变化：

- `visibility`：目标主题的品牌提及或平均提及位置是否变化；无提及时不写排名改善。
- `citation`：目标 Blog、正式页面或第三方来源是否开始被引用，或错误来源是否仍被采用。
- `brand_expression`：具体负面认知、重构表达或已有优势是否仍按原强度出现。
- `accuracy`：已确认的错误主张是否被纠正，回答采用的事实是否与官方真值一致。

复测不是换一套问法；同一市场、语言、采集窗口和 Prompt 要重新跑同一批 prompts，再看 visibility、citation、brand_expression 和 accuracy 是否发生变化。复测回答的是“这次动作有没有进入诊断数据”——最低验收标准是“做过的具体动作是否出现在复测数据里”（新页面是否被引用、更新的表述是否被采用、错误主张是否消失），不是“它带来了多少业务”。品牌表达类信号（负面重构、优势强化）的变化通常慢于可见度和引用，复测预期中应保留这一节奏差异，不因短期未变判定动作无效。售前诊断不接入 AI Referral Traffic、线索和成交归因，也不承诺排名、推荐或成交。

## 跨模块综合

跨模块只做证据允许的关系判断：

- `官网已有引用 + 可见度为零` → “官网内容能被找到，但品牌在可见度统计中仍未被提到。”
- `设计正向 + 信任负向` → “回答能识别产品特点，但采购方仍缺少具体资料来完成判断。”
- `竞品获得提及 + 明确主题证据` → “竞品优势集中于这些主题”；没有主题证据不得补写原因。
- `外部榜单/评测主导 + 品牌缺席` → “第三方比较内容是需要补强的证据渠道”；不得承诺进入后必然提升指标。
- `品牌缺席 + 多个平台一致缺席` → “可比平台均未提及品牌，缺席并非单一平台现象”；不得写成全网都没有品牌认知。
- `发现为零 + 评价正向` → “品牌具备基础好感或可识别特点，但尚未在用户未指定品牌时自然进入回答”；不得写“口碑没有转化”。
- `验证采用官网事实 + 发现官网引用为零` → “官网事实能够被读取，但尚未进入通用发现与选型语境”；不得归因于页面质量或平台机制。
- `两个平台都不提品牌 + 竞品占位不同` → “品牌缺席方向一致，但当前竞争结构存在平台差异”；分别说明各平台由谁占位。
- `评价正向 + 竞品结果偏负向` → “单独评价中的好感尚未形成直接比较说服力”；必须说明负向比较集中在哪些有证据的维度。
- `不同主题由不同竞品占位` → “竞争结构随主题改变”；不得用整体领先竞品解释所有主题。
- `各平台均有提及 + 平均提及位置分歧` → “品牌进入状态较稳定，但竞争位置尚未形成跨平台一致性”；不得把分歧直接归因于内容或来源。
- `决胜回答胜率 + 正面对比主题` → “模型明确选边时品牌的相对胜势，以及优势/劣势集中在哪些维度”；不得混入平局计算另一个总体胜率。
- `M08 missing/conflicting + Attribute 诊断` → “当前购买框架尚未给该差异点稳定的评价位置，或与预设定位存在冲突”；不得写成低 Visibility 的确定原因。
- `主题跨平台分歧 + Attribute/M08 证据` → “该主题的跨平台判断尚未稳定；现有属性或购买框架证据可解释差异落在哪个方面”；不得给 Attribute 另建跨平台状态，也不得写成确定原因。

还可使用以下通用组合，但必须同时具备对应数据：

| 可见度状态 | 证据或表达状态 | 可得出的关系判断 |
|---|---|---|
| 可见度统计未提及 | 情绪分析评价正向 | 品牌特点能被识别，但在可见度统计中仍未被提到；不能说正向口碑“没有转化” |
| 已有提及 | 负向风险集中且有多条支持 | 可见度不是唯一问题，购买信任或信息完整性也是需要处理的独立风险 |
| 官网已有引用 | 引用集中在首页、联系页等存在性页面 | 官网能被找到，但当前页面更多证明品牌存在，采购判断所需信息仍有限 |
| 官网决策页已有引用 | 外部比较、评测或独立评价覆盖弱 | 一方事实已有基础，第三方验证仍是独立缺口 |
| 正向差异点明确 | 风险集中在证书、来源、售后或政策 | 产品特点与购买信任之间存在证据张力，应分别陈述优势和阻碍 |
| 可见度状态明确 | 跨平台结果一致 | 当前主诊断在可比平台上相对稳定，但不外推为全网共识 |
| 可见度状态明确 | 跨平台结果分歧 | 总体指标掩盖了平台差异，应同时说明哪些平台进入、哪些平台缺席或位置不稳 |
| 预设差异点明确 | M08 为 `included` | 当前购买框架已经提供评价该差异点的位置，但仍不能证明目标品牌会被选中 |
| 预设差异点明确 | M08 为 `missing/conflicting` | 当前购买框架尚未支持或明确冲突于该差异点，差异化表达与市场选择标准之间存在缺口 |

不要求每份报告强行形成跨模块结论。只有两个模块指向同一问题，或它们之间的差异会改变优先级时才综合；否则保留各自边界比制造联系更可靠。

使用“同时存在”“表明仅凭……不足”“与……一致”等有限措辞。除非输入提供直接因果证据，否则禁用“导致”“因此必然”“没有转化”“提升后即可”等表达。

## 去重与取舍

定稿时逐条标记句子的角色：

```text
事实 → 诊断 → 边界/关系 → 优先级 → 行动
```

同一个数字可以在数据模块和行动依据中各出现一次，但两处作用必须不同。若删除一句不改变客户判断、优先级或行动，就删除。品牌、行业和 Task 特有的洞察只从当前证据生成，不固化为通用模板。

## 最终自检

- 是否先判断“缺席”还是“位置落后”，并正确处理 `0/N`、`0/0` 和 `-`？
- 是否先拆六类诊断意图，再解释整体指标，并避免把整体提及率直接写成发现表现？
- 客户文案是否统一使用“发现、竞品、验证、准确性、评价、品类认知”，且未出现“纯发现型”等另造口径？
- 是否把题面含品牌造成的 100% 提及或首次位置第 1 写成了优势、稳定表现或维护项？
- 是否把指定竞品声量误写成全市场份额？
- 是否把平均提及位置误写成模型推荐强弱？
- 是否把情绪样本当成可见度证据，或反过来？
- 是否把回答中的提及、正向评价或询价建议误写成真实供应商名单、真实询价或采购结果？
- 客户提供的竞品全部未提及时，是否仍错误判断竞品选错或建议替换？
- 是否把单条证据放大成高频、普遍或共识？
- 是否区分官网可发现、决策证据和第三方承接？
- 官网页面机会是否先扫描主题/Tag 相关候选，再分别判断页面相关性与 Citation 状态，而不是只检查已引用页面？
- 页面修改是否落到具体能力、Claim 或问题缺口，同时避免把 Attribute 做成独立客户字段？
- 跨平台比较是否只使用同市场、同语言、同采集窗口和匹配 Discovery Prompt？
- 是否把提及一致性与平均提及位置一致性分开，并正确处理全部未提及时的位置不适用？
- 是否把可比平台一致误写成全网共识，或把平台分歧直接写成原因和单平台优化行动？
- 是否只输出整体与主题两级跨平台判断，并避免把 Attribute 单列为共识或排名—可见度状态？
- 是否只把决胜回答胜率称为竞品胜率，并保留双方胜场、平局、无法判断和无决胜回答时的 `null` 边界？
- 是否误写了总体胜率，或把情绪、提及率、品牌常识混入竞品优劣势？
- Market Perception 是否使用后端正式状态并进入独立 M08，而不是写成 Visibility、竞品输赢因果或归因？
- 是否至少形成一个跨模块但不过度因果的判断？
- 是否检查了整体、主题、平台共同与差异、诊断意图、引用和跨维度张力，而不是只重复整体数字？
- 是否把整体、主题、平台和诊断意图都作为分析维度，而没有人为增加“正式结论/切片观察”层级？
- 是否在没有明确采购场景时反复使用“采购”，导致发现、验证、评价和品类认知的含义被压扁？
- 是否每个模块都增加新信息，而不是反复罗列同一组数字？
- 是否让行动对应不同问题，并且没有超出后端方向？
- 是否只有后端提供 `route_type` 时才区分信息理解、第三方信任、错误事实、负面认知和优势强化，避免把所有低表现都写成新增内容？
- 站内行动是否按“承载页面是否存在与可抽取 → 还能在哪些页面自然补入 → 如何自然补入”展开，而不是只写“新建页面”或把一个页面当作足够？
- 异议行动是否处理了“无内容时先建承载”“真实短板承认并框定”“重构跨多个 surface”，而没有写成否认或单页修补？
- 站外行动是否写清要改变来源的哪句表述，而不是写成获取外链；引用结构支持时是否点出了“引用竞品但未引用目标品牌”的承接候选？
- 负面认知是否区分了跨问题重复与单题触发的广度差异？
- 复测预期是否包含“做过的动作是否出现在数据里”这一最低标准，并保留品牌表达信号变化更慢的节奏边界？
- 是否写清官网 Blog、第三方信源、非 Blog 官网正式页面和内部材料的责任边界，并避免把客户页面写成我方直接修改上线？
- `expected_impact` 是否对应可见度、引用、品牌表达或准确性复测，而没有扩写成 AI Referral Traffic、线索或成交归因？
- 是否隐藏内部题型和过程术语，同时在必要处只用可见度统计与情绪分析说明范围？
- 是否仍有自然候选、证据承接、实绩验证、系统级验证、RFQ 等需要客户二次翻译的词？
- 是否仍有只有需核实但没有对象、场景和材料的空话？
