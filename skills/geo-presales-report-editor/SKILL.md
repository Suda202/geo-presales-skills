# GEO 售前报告编辑

## 负责什么

把公司后端已确认的统计、筛选聚合、表达证据和行动方向，编辑成客户能够据此判断“问题在哪里、为什么重要、先做什么”的报告结论。唯一正式交付是供用户确认和上传的 CSV；不负责重新审计或计算底层数据，也不在销售后台或报告页面修改、提交、上传内容。

输入按以下顺序定位：用户提供的报告 CSV、当前附件或已确认统计文件、当前 Task/品牌对应的运行目录或统计包、已配置的只读后端适配器。已有 CSV 时直接编辑 CSV，不要求先重建报告。页面链接只可用于定位 Task 或只读核对证据；不得在页面内回填或上传。

## 执行骨架

1. **现成 CSV 模式（首选）**：确认它符合五列表头后，只改允许回填的报告内容，保留编码、换行、字段路径和后台结构；输出新的 CSV 供用户确认。
2. **后端统计包模式**：尚无 CSV 时，才用 `scripts/backend_report.py prepare` 冻结 v2 输入，完成各事实模块并 `finalize` 生成 CSV。
3. 两种模式都先按“发现、竞品、验证、准确性、评价、品类认知”拆分，再综合整体、主题、平台、引用和跨维度张力。整体提及率不得直接当作发现表现。
4. 只有后端提供 `action_context` 时才编辑行动；准确性没有正式样本时只说明未覆盖，不补判。品类认知类问题没有后端正式属性对齐结果时省略，不从原始回答或品牌提及反推。
5. 最终只交付 CSV 文件；用户确认后由用户上传，不替用户操作页面或提交后台。

后端统计包模式中的每个任务只处理自己的资源文件，并通过 `submit-task` 校验证据、数字和模块边界。现成 CSV 模式同样不得把多个范围混成无证据的大段总结。

## 诊断—路由方法

行动结论遵循“先给问题定性，再决定在哪解决”的顺序，路由类型由后端 `route_type` 正式给出，报告侧只表述、不自判：

- 缺席且属性未被识别（低进入、低验证）→ 能力理解缺口：把事实放到适合承载它的站内页面，写清是什么、适用于谁。
- 已被识别但外部佐证不足（低进入、验证充分）→ 第三方信任缺口：以独立信源承接，官网自述不作为主要解法。
- 已形成具体负面认知 → 负面认知重构：基于真实事实说明适用范围和取舍，重构而非辩解，也不否认真实短板。
- 已确认的优势 → 优势强化：在相关站内页面和第三方信源多点强化，抢在竞品占据表达前。

站内与站外分工固定：站内页面负责让事实能被找到和抽取，站外信源负责独立佐证。同一能力需要在站内多个相关语境出现，不按“一个关键词一个页面”思路只补单页；站内建议按“承载页面是否存在且可抽取 → 还能在哪些页面自然补入（优先已被引用、高引用量、高权重页面）→ 如何自然补入（FAQ 可用，编织进正文更持久，均须通过编辑测试）”展开。站外承接优先级为“更新已有提及 → 进入已有信源 → 新建信源”，不默认新建内容；站外价值在来源怎么描述品牌，不在链接本身。异议行动遵循“无内容先建承载、真实短板承认并框定、重构跨多个 surface”，不写否认。

客户文案按“可被抽取”而非 SEO 写：用直接、具体、AI 能干净引用的句子；提及在自然处补入，不硬塞。复测沿用同口径 Prompt 重跑，只看可见度、引用、品牌表达和准确性的变化，最低验收是“做过的动作是否出现在复测数据里”；不承诺流量、线索或成交。

## 硬边界

> 模块代码：M05 = 评价/情绪，M06 = 行动建议，M07 = 平台差异，M08 = 品类认知（Market Perception）。完整映射见 [跨 skill 规范映射](../shared/canonical-intent-mapping.md)。

- 指标、分母、分档、行动路由和优先级只使用后端结果；不从明细重算。正式可见度与主要引用生态只用 `diagnostic_intent=discovery`；情绪直接使用完整 `analysis_type=sentiment` 结果，不再按 `diagnostic_intent`、Discovery/Evaluation、通用题/品牌题或其他意图二次筛选。
- 客户文案中的六类诊断标签固定为“发现、竞品、验证、准确性、评价、品类认知”；标签单独展示时使用这些名称，在结论句中统一写成“发现类问题、竞品类问题、验证类问题、准确性类问题、评价类问题、品类认知类问题”。不得混用“发现型、纯发现型、竞品比较、功能核实、准确性诊断、品牌评价”等别名。
- 竞品、验证或评价问题若题面已经出现品牌，品牌被提及及平均提及位置不进入客户文案；不得写成优势、稳定表现或维护项，也不得补写提问方式、题型机制或指标过滤解释。需要说明整体与发现的统计范围时，只写各范围的有效样本和结果。
- 严格区分“提及率排名”和“平均提及位置”：前者按 Discovery 提及率比较品牌名次，后者按品牌在被提及的 Discovery 回答正文中的首次合格出现位置取平均。无提及时平均提及位置写 `-`，不写第 0 位；两者都不得推断推荐强弱。
- 客户文案、CSV、任务说明、字段说明和校验统一使用“平均提及位置”和“引用份额”；不得输出废弃名称“平均提及排名”“引用占比”“官网引用占比”。
- 客户文案只写会改变判断或行动的事实与结论；删除“该指标表示……”“只表示……”“不能视为……”“不代表……”“不等于……”“据此不能……”等指标释义、解读限制、筛选机制和题型说明。此类边界只保留在内部规则、证据校验或用户明确要求的口径说明中。
- 竞品只保留决胜回答胜率；无决胜回答为 `null`，不另写总体胜率。优劣势只取有样本和引用的正面对比证据；指定竞品声量不等于全市场份额。
- Attribute 由内部主题或 Tag 承载，不生成独立客户模块、上传字段或跨平台状态。页面机会必须来自主题/Tag 官网候选扫描，并分开判断相关性与 Citation；内部 Attribute/Prompt Gap 对外改写为具体能力、Claim 或问题缺口。客户文案一律使用“主题”，不得出现 `Topic/topic`。
- 客户竞品全零时只写当前无法比较；不判断竞品选错。少量证据不写成高频或共识，并存不写成因果，回答不写成真实询价、供应商名单或采购结果。
- M05 只写后端分档。M06 只接受 `action_context` 路由，不因单个低指标判断内容不足，不新增方向或效果承诺；复测只看可见度、引用、品牌表达或准确性，不接入流量、线索和成交归因。
- 有正式 M07 时只使用其整体/主题结果；没有 M07 但有同口径、后端已确认的平台筛选聚合时，可直接比较已确认数值，写平台共同结论与差异结论，但不得自造状态枚举、阈值或共识强度。M08 不写成 Visibility、输赢原因或归因。
- 每条非空结论必须有真实证据引用，所有数字必须存在于对应资源。
- 不使用“正式结论/切片观察”区分分析等级，也不在客户文案中反复使用“本批”；整体、主题、平台和诊断意图都是不同数据维度的分析结论。按后端实际覆盖保留样本范围，不外推全网、不猜机制、不把相关性写成因果。

## 客户文案门禁

- 事实与结论在前，只保留会改变判断、优先级或行动的句子；不用内部题型、Attribute/Prompt Gap 或需要二次翻译的术语。
- 每份报告按后端实际覆盖检查整体、主题、平台共同与差异、已覆盖的诊断意图、引用结构和跨维度张力；未覆盖的诊断维度省略，不为完整感补句子。题面含品牌造成的必然提及及其元解释均不得进入客户文案。
- 不使用“通用回答、通用选购回答”等虚构口径；需要描述 Discovery 范围时统一写“发现类问题”或“发现类问题的回答”。
- 品类认知类问题只分析“主题下实际形成的选择标准，是否覆盖问题中预设的关键属性，以及这些属性是否与品牌预先配置的目标差异点契合”。优先使用后端标准化的 `market_criteria`、问题 `target_attributes` 和品牌预设差异点逐项对齐，输出已纳入、缺失、冲突或证据不足；不得把品牌提及次数、提及率或排名写成品类认知结论，也不得从品牌表达或原始回答自行推断选择标准。没有后端正式对齐结果时直接省略。
- 不把所有分析压成“采购”叙事：发现讲用户未指定品牌时能否进入回答，竞品讲相对表现，验证讲事实识别，评价讲品牌认知，品类认知讲选择标准，准确性讲事实正误。只有题目明确对应采购方、制造商初选或选型时才使用“采购”。
- 风险写清场景、缺口和材料；行动写清问题、载体、双方责任和复测信号，多条行动不得重复“补内容”。
- 页面机会按四象限与后端 priority 表达：高相关已引用强化能力，高相关未引用作为 Citation Gap，低相关页面不为当前主题/Tag 硬改。
- 诊断覆盖整个官网和外部信源。我方直接交付只限官网 Blog 与约定第三方内容；非 Blog 页面由我方给清单/建议文案、客户修改上线。内部事实和审批由客户相关团队提供或确认，只有后端确认时才点名部门。
- 产品规格、价格、政策、集成和服务承诺回到对应正式页面，不为适配交付全部塞进 Blog。

## 完成门禁

按结论综合规则自检：正式可见度和主要引用生态只含 Discovery；情绪已完整保留所有 `analysis_type=sentiment` 结果，没有再按诊断意图筛选；整体指标与发现表现已拆开；提及率排名与平均提及位置没有混淆；诊断标签及“类问题”句式统一；客户文案只使用“主题”“平均提及位置”和“引用份额”；仅覆盖后端有证据的诊断维度；题面含品牌造成的必然提及及其元解释均未进入客户文案；品类认知没有被误写成品牌提及分析；整体、主题、平台、引用与跨维度关系已按证据覆盖；范围与胜率分母正确；不把回答写成真实采购结果；行动有后端依据且不重复。最后删除需二次翻译、不改变判断或只解释题型机制的句子。

修改 Skill 的触发范围或职责边界后，运行 [路由回归用例](evals/trigger_cases.json)，确认结论编辑不会与指标审计、Prompt 生成、回答采集或报告渲染混淆。

正式产物必须保持 UTF-8 BOM、CRLF 和固定 `module,path,index,field,value` 五列。空的 `p0/p1/p2` 行仍保留，值留空。不要上传内部 JSON，不生成 HTML/PDF，也不直接操作报告页面。
